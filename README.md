# ymonitor — мониторинг дерева публичных пиров Yggdrasil

Коллектор опрашивает все публичные пиры сети Yggdrasil и складывает их текущие
координаты (путь в дереве от корня) и историю их изменений в D1. Поверх —
публичный JSON API на Cloudflare Worker: чтение без какой-либо авторизации,
запись — только коллектору, по bearer-токену.

Дальше на этих данных можно: рисовать карту дерева, следить за отвалом
сегментов, выбирать «ближайший» пир по координатам и анализировать
стабильность пиров.

## Как это работает

```
                       ┌────────────────────────┐
 publicnodes.json ───► │  ymonitor (Go, docker) │
 (ключи уже внутри,    │  встроенная нода       │
  обновление ~5 мин)   │  yggdrasil 0.5, no TUN │
                       └───────┬───────┬────────┘
             probe каждому пиру│       │POST /v1/ingest (Bearer)
          (1 пакет → lookup →   │       ▼
           подписанный ответ)   │   ┌──────────────┐   GET без авторизации
                               │   │ Cloudflare   │◄─────── карта, история,
                               └──►│ Worker + D1  │        аналитика
                                   └──────────────┘
```

**Ключевой механизм — «прощупывание» (probe).** Координаты узлов в Yggdrasil
0.5 не рассылаются всей сети: нода узнаёт путь к адресату, только отправив ему
трафик (lookup). Поэтому каждый цикл монитор отправляет по одному пакету на
каждый публичный пир; живой пир отвечает подписанным уведомлением со своим
текущим путём от корня, мёртвый — молчит. Так один опрос даёт и координаты,
и признак живости. Проверено на живой сети: отвечают 99 из 100 пиров,
которые краулер publicnodes считает живыми (замер: `cmd/spike`).

Пакет-проба — один мусорный байт; он доезжает до удалённой ноды как
невалидный IPv6 и отбрасывается её ядром. Изучение пути происходит ниже
IP-уровня и на удалённой стороне ничего не требует.

## Состав репозитория

```
cmd/ymonitor/          коллектор (демон и -once)
cmd/spike/             диагностический прогон: сверка probe-метода с publicnodes
internal/ygg/          обёртка над yggdrasil-go core (встроенная нода без TUN)
internal/collector/    список пиров, probe-сэмплер, дифф+дебаунс, poller
internal/store/        HTTP-клиент worker'а и WAL (дозапись при сбоях)
worker/                Cloudflare Worker + миграции D1 (schema)
deploy/                Dockerfile, .env.example
docker-compose.yml     локальный запуск коллектора
```

## Схема данных (D1)

```sql
peers(key PK, ipv6, endpoints JSON, coords, updated_at, last_answer_ts, country)
events(ts, peer_key, old_coords, new_coords)              -- только изменения
meta('poll_ts')                                           -- свежесть данных
```

- `coords` — путь от корня, например `390.4.74`. `""` (пустая строка) —
  корневой узел. `NULL` — пир сейчас не в дереве.
- `country` — страна из файла public-peers, где числится пир (для флагов).
- Снапшоты истории НЕ хранятся: любое прошлое состояние восстанавливается
  перемоткой `events`, это делает браузер (см. UI).
- `last_answer_ts` — время последнего опроса, на котором пир ответил пробу;
  `NULL` — никогда не отвечал. Основано на нём — stateless-дебаунс (см. ниже).
- `events`: строка пишется только при изменении; `old_coords=NULL` —
  появление, `new_coords=NULL` — исчезновение (после дебаунса).
- Идемпотентность: повторная отправка батча не создаёт дублей (unique index).

## Запуск API (Cloudflare Worker + D1, бесплатно)

```bash
cd worker
npm install

npx wrangler login
cp wrangler.toml.example wrangler.toml   # затем вписать в него database_id
npx wrangler d1 create public-peers      # скопируйте database_id в wrangler.toml
npm run migrate:remote                   # применить схему
npx wrangler secret put INGEST_TOKEN     # придумайте токен для коллектора
npm run deploy                           # URL вида https://ymonitor-api.<sub>.workers.dev
```

`wrangler.toml` с реальным `database_id` не коммитится (в `.gitignore`);
в репо лежит `wrangler.toml.example`. Binding должен называться
`DB` — на это имя рассчитан код.

Локальная проверка без аккаунта: `cp .env.example .dev.vars 2>/dev/null; echo "INGEST_TOKEN=dev" > .dev.vars && npm run migrate:local && npm run dev` → http://localhost:8787.

## Запуск коллектора (Docker)

```bash
cp deploy/.env.example .env     # вписать WORKER_URL и INGEST_TOKEN
docker compose up -d            # демон: цикл каждые 5 минут
curl -s localhost:8080/healthz  # самочувствие
```

Разовый запуск (обновить данные и выйти) — тем же образом на любом хостинге:

```bash
docker run --rm \
  -e WORKER_URL=https://ymonitor-api.<sub>.workers.dev \
  -e INGEST_TOKEN=<токен> \
  -v ymonitor-data:/data \
  ghcr.io/drewcyber/public-peers-map:latest -once
```

Без Docker: `go build ./cmd/ymonitor && WORKER_URL=... INGEST_TOKEN=... ./ymonitor`.

### Запуск коллектора из GitHub Actions (без своего хостинга)

В репозитории есть workflow `collect` (`.github/workflows/collect.yml`) с
ручным запуском: **Actions → collect → Run workflow**. Раннер скачивает
образ из GHCR и выполняет `-once`. Требуются:

- Repository variable `WORKER_URL`;
- Repository secret `INGEST_TOKEN`;
- образ `ghcr.io/drewcyber/public-peers-map:latest` (публикуется CI из `main`).

Workflow запускается автоматически каждые 30 минут (cron, время UTC) и
вручную (Actions → collect → Run workflow); `POLL_INTERVAL=30m` /
`VANISH_AFTER=90m` в шаге ниже подобраны под этот интервал.

Не запускайте демон и `-once` одновременно — события задвоятся (дедуп
защитит от дублей, но не от лишних циклов).

## Конфигурация

| Переменная / флаг | По умолчанию | Смысл |
|---|---|---|
| `WORKER_URL` `-worker-url` | — (обязательно) | URL worker'а |
| `INGEST_TOKEN` `-ingest-token` | — (обязательно) | bearer-токен записи |
| `ONCE` `-once` | `false` | один цикл и выход |
| `ONCE_TIMEOUT` `-once-timeout` | `10m` | общий таймаут `-once` |
| `PEERS` `-peers` | авто | свои пиринги (csv URI); иначе выбираются из списка |
| `CUSTOM_PEERS` `-custom-peers` | — | csv URI пиров, которых нет в publicnodes.json: монитор держит с ними прямой пиринг, учит ключ из handshake и опрашивает наравне со списком; у упавшего такого пира ключ восстанавливается из его строки в `peers` (по endpoint), так что vanish работает и между отдельными `-once`-прогонами |
| `POLL_INTERVAL` `-interval` | `5m` | период опроса |
| `LIST_TTL` `-list-ttl` | `24h` | как часто перечитывать publicnodes.json |
| `VANISH_AFTER` `-vanish-after` | `0` = 3×интервал | сколько времени пир может молчать, оставаясь «в дереве», прежде чем получить vanish (длительность, напр. `15m`) |
| `HEARTBEAT_EVERY` `-heartbeat-every` | `15m` | как часто перезаписывать строки стабильных пиров, чтобы `last_answer_ts` не устаревал |
| `PROBE_PACE` `-probe-pace` | `50ms` | пауза между пробами |
| `PROBE_QUIET` `-probe-quiet` | `20s` | тишина, после которой сэмпл завершается |
| `PROBE_TIMEOUT` `-probe-timeout` | `120s` | жёсткий лимит сэмпла |
| `DATA_DIR` `-data-dir` | `./data` | ключ ноды и WAL |
| `HEALTH_ADDR` `-health` | `127.0.0.1:8080` | health-эндпоинт (в docker — `0.0.0.0:8080`) |

## API

Все GET открыты (CORS `*`), формат — JSON.

| Метод и путь | Что возвращает |
|---|---|
| `GET /v1/peers` | все пиры: `key`, `ipv6`, `endpoints[]`, `coords` (или `null`), `updated_at`; плюс `as_of` — время последнего опроса |
| `GET /v1/peers/{key}` | один пир |
| `GET /v1/peers/{key}/history?from=&to=&limit=` | события координат пира |
| `GET /v1/tree` | снимок дерева для отрисовки: `peers[]` с `coords`, `key`, `ipv6`, `endpoints`, `country` (только кто сейчас в дереве) — всё для карты за один запрос. Точки и рёбра клиент выводит сам из префиксов coords |
| `GET /v1/events?from=&to=&limit=` | полный журнал изменений координат (по возрастанию ts) — для таймлайна и восстановления истории на клиенте |
| `GET /v1/stats` | счётчики: всего пиров, в дереве, событий, событий за 24ч, `as_of` |
| `POST /v1/ingest` | запись батча (только коллектор, `Authorization: Bearer …`) |
| `GET /healthz` (worker) | живость API |

Примеры:

```bash
curl -s https://ymonitor-api.<sub>.workers.dev/v1/peers | jq '.peers[0]'
# {"key":"0000…","ipv6":"230:f23c:…","endpoints":["quic://…","tcp://…"],"coords":"","updated_at":…,"last_answer_ts":…}

curl -s …/v1/peers/0000…4ae/history | jq '.events[-3:]'
# последняя смена координат узла

curl -s …/v1/tree | jq '{as_of, n: (.peers|length), root: (.peers[]|select(.coords=="")|.ipv6)}'
```

**Контракт отрисовки дерева** (`/v1/tree` → UI):
- `coords` — путь от корня; `""` — сам корень (это публичный пир);
- родитель узла `X` = `X` без последнего сегмента; корень — родитель всех
  одно-сегментных координат;
- каждый строгий префикс любой coords — «точка» (непубличный узел); цепочки
  одиноких точек можно сжимать для читаемости;
- клик по пиру → `key` готов для запроса `/v1/peers/{key}` и `/history`.

## Поведение и семантика данных

- **Карта строится из одних координат**: каждый префикс coords — «точка»
  (`1.2.3` и `1.2.4` дают общую точку `1.2`), публичный пир — подписанная
  вершина. Ключи непубличных узлов не хранятся.
- **Stateless-дебаунс исчезновений**: пир помечается пропавшим, если он
  «в дереве», но не отвечал дольше `VANISH_AFTER` (по умолчанию 3 интервала,
  ~15 минут при опросе раз в 5 минут). Счётчик молчаний живёт не в памяти
  процесса, а в колонке `last_answer_ts` — поэтому корректно работают любые
  комбинации: демон, одиночные `-once`-запуски, несколько коллекторов
  параллельно на разных хостах.
- **Heartbeat**: строки стабильных (ответивших, но не изменившихся) пиров
  перезаписываются не чаще раза в `HEARTBEAT_EVERY` — это обновляет
  `last_answer_ts` для других коллекторов, не сжигая дневной лимит записей
  D1 (~100 строк на 15 минут при 400 пирах — с большим запасом).
- **Защита от мусора в истории**: если за цикл ответило подозрительно мало
  пиров (<30 % от живых по списку — например, у монитора отвалились
  пиринги), цикл пропускается целиком, состояние не трогается.
- **WAL**: батч пишется на диск до отправки; недоставленное догоняется при
  следующем цикле. Повторная доставка безопасна благодаря дедупу в D1.
- **Свежесть**: поле `as_of` = время последнего успешного опроса
  (`meta.poll_ts`).
- **Бюджет бесплатного D1** (100k записей/день): в нормальном режиме пишутся
  только изменившиеся строки — десятки записей на цикл.

## Ограничения

- Координаты пира видны только на момент опроса; между опросами (5 мин)
  кратковременные переезды не фиксируются.
- Пиры, исчезнувшие из publicnodes.json, остаются в `peers` со старыми
  данными (краулер записи не удаляет, на практике список только растёт).
- `getTree`/`getPaths` — внутренний API ironwood; при мажорном обновлении
  yggdrasil-go нужен ручный прогон `cmd/spike`.

## UI: карта дерева (GitHub Pages)

`docs/index.html` — самодостаточная страница без зависимостей и сборки.
При загрузке делает ровно два запроса (`/v1/tree` + `/v1/events`) и дальше
работает полностью локально: карточки пиров, таймлайн и поиск не ходят в API.

- Карта: SVG-дерево из префиксов координат, каждая точка подписана своими
  координатами; корень — янтарный, публичный пир — голубой, точка — серая.
  Зум колесом/пинчем/кнопками, пан перетаскиванием, двойной тап/клик —
  приблизить (вписать в экран — кнопка ⤢), на тачскрине работает и жест
  «тап — тап с удержанием — вверх/вниз» (движение вниз приближает).
- Карточка пира (клик по точке или подписи): координата, страна с флагом,
  ipv6, эндпоинты — из уже загруженных данных, без сети.
- Таймлайн внизу — «объём торгов»: столбик на каждый момент изменений
  (высота = число событий), клик/стрелки ◀ ▶ переключают состояние, кнопка
  «сейчас» возвращает живую карту. Переключение истории мгновенное: состояние
  на любой ts восстанавливается перемоткой журнала событий в браузере.
- Опция «изменения»: пиры, сменившие координаты с предыдущего состояния,
  подсвечиваются оранжевым (в мета-строке +появилось / −пропало / ~переехало).
- Опция «флаги»: флаг страны рядом с подписью пира.
- Поиск: coords / ipv6 / key / endpoint / страна. Частичное совпадение —
  список, точные координаты — прыжок к ноде с подсветкой (карта сама
  переключается на состояние, где нода стоит в этих координатах).
  Горячие клавиши: Ctrl/Cmd+F и «/» — фокус в поиск, ←/→ — навигация по
  таймлайну, Esc — закрыть карточку.
- Язык интерфейса RU/EN: кнопка в шапке, выбор определяется автоматически
  по локали браузера и сохраняется.

Включение: **Settings → Pages → Deploy from a branch → main → /docs**.
Адрес страницы: `https://<owner>.github.io/public-peers-map/`.
URL API задаётся константой `API_URL` в начале скрипта в `docs/index.html`.
